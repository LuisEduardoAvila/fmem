# File Summarizer Specification

> Generated by spec-gen v1.0.0 on 2026-02-28

## Purpose

Extracts brief summaries from files to provide context for LLM and search results. Handles special formatting for memory/log-style files versus regular documents.

## Requirements

### Requirement: SummarizeFile

The system SHALL extract brief summaries (50-150 characters) from file content

#### Scenario: MemoryFileSummary
- **GIVEN** memory file content "## Work Updates\nCompleted tasks\n## System Fixes\nAll done"
- **WHEN** summarize is called with filepath "memory/2026-02-28.md"
- **THEN** detects memory file format and extracts topics "Work Updates", "System Fixes"
- **AND** counts status keywords (COMPLETED, ✅, DONE)
- **AND** returns summary "2026-02-28: 2 topics, 1 COMPLETED, (Work Updates, System Fixes)"

#### Scenario: RegularFileSummary
- **GIVEN** document content "# Project Title\nDescription here\n\n## Overview\nMore text"
- **WHEN** summarize is called with filepath "docs/readme.md"
- **THEN** extracts first # heading "Project Title"
- **AND** extracts first meaningful paragraph "Description here"
- **AND** returns summary "Project Title • Description here"

#### Scenario: MEMORYmdFileSummary
- **GIVEN** file "MEMORY.md" with multiple ## sections
- **WHEN** summarize is called
- **THEN** treats as memory file and extracts date/topics
- **AND** returns summary with count of topics and completion status

### Requirement: DetectMemoryFile

The system SHALL detect if a file is a memory/log-style file

#### Scenario: DatePatternDetection
- **GIVEN** filepath contains "memory/2026-02-28.md"
- **WHEN** _is_memory_file is called
- **THEN** returns True based on date pattern YYYY-MM-DD in filename
- **AND** returns True due to "memory" in path

#### Scenario: MEMORYmdDetection
- **GIVEN** filepath is "MEMORY.md" or contains "memory.md"
- **WHEN** _is_memory_file is called
- **THEN** returns True

#### Scenario: RegularFileDetection
- **GIVEN** filepath is "docs/project.md"
- **WHEN** _is_memory_file is called
- **THEN** returns False

### Requirement: ExtractTopics

The system SHALL extract section topics from memory file content

#### Scenario: ExtractAllHeadings
- **GIVEN** content with ## headings "Work Updates", "System Fixes", "User Feedback"
- **WHEN** extract_topics is called with max_topics=10
- **THEN** returns ["Work Updates", "System Fixes", "User Feedback"]
- **AND** removes duplicates while preserving order

#### Scenario: EnforceTopicLimit
- **GIVEN** content with 15 ## headings
- **WHEN** extract_topics is called with max_topics=5
- **THEN** returns only first 5 unique topics

### Requirement: CountStatusItems

The system SHALL count status indicators in memory file content

#### Scenario: CountCompletedItems
- **GIVEN** content with 3 occurrences of "COMPLETED", 2 of "✅", 1 of "DONE"
- **WHEN** count_status_items is called
- **THEN** returns {'completed': 6, 'in_progress': 0}

#### Scenario: CountInProgressItems
- **GIVEN** content with 2 occurrences of "IN PROGRESS", 1 of "🔄", 2 of "→"
- **WHEN** count_status_items is called
- **THEN** returns {'completed': 0, 'in_progress': 5}

## Technical Notes

- **Input**: File content (str), filepath (str)
- **Output**: Summary string (50-150 chars)
- **Special formats**: Memory files (YYYY-MM-DD.md, MEMORY.md), regular documents
- **Extraction strategy**: Topics from ## headings for memory files, # heading + first paragraph for regular files
