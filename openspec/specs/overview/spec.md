## Purpose

OpenSpec is a command-line tool that turns local files into an intelligent, searchable memory
system. It embeds documents and daily notes, then lets users retrieve relevant passages via
natural-language queries, supporting summarization and review workflows without external services
beyond the embedding API.

## Key Capabilities

### Requirement: SystemCapabilities

The system SHALL provide the following capabilities:
- SQLite used for metadata and vector storage to keep system fully local
- EmbeddingService caches generated vectors on disk to avoid redundant API calls and enforces rate limiting to respect provider quotas
- DocumentManager centralizes chunking strategy (configurable chunk vs. section mode) to ensure consistency between embedding and retrieval stages
- Dependency graph is acyclic (0 cycles) enforcing strict layered direction and preventing circular imports
- Batch indexing with optional progress indicator keeps CLI responsive for large directories

### Requirement: DataFlow

The system SHALL process data through defined layers:

#### Scenario: StandardDataFlow
- **GIVEN** an incoming request
- **WHEN** the request is processed
- **THEN** data flows through: File or memory text → DocumentManager validation → chunking → EmbeddingService (with cache/rate-limit) → vector + metadata → DatabaseService SQLite storage → user query → EmbeddingService query vector → DatabaseService similarity search → ranked chunks returned to CLI.

## Technical Notes

- **Architecture Style**: layered (strict dependency hierarchy with service layer encapsulating infrastructure; chosen to isolate SQLite, file-system, and external-API concerns from the retrieval domain logic).
- **Security Model**: OS-level file permissions only; no auth layer—users rely on shell access control; input file paths are validated to prevent directory traversal before indexing.
- **External Integrations**: OpenAI (or compatible) embedding API, local SQLite database, local file-system workspace/memory/
